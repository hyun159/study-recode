# 이해한 내용
```
was?

클라이언츠 ---요청---> 서버  

과거  
스레드 메모리 할당 -> 처리 -> 종료
DB 소켓 연결 -> 처리 -> 종료


현재  
메모리 공간 확보(쓰레드)와 DB연결을 미리 확보 -> 데이터 처리 -> 스레드반납, DB연결 반납  
was는 백엔드 로직이 사용할 메모리와 DB 네트워크 정보가 적힌 소켓을 미리 할당하여 많은 요청을 빠르게 처리할 수 있다.  


소켓은 IP, 포트, 프로토콜이 적혀있는 메모리상에 존재하는 구조체  
파일로 추상화시켜놓고 프로세스가 참조하도록 디스크립터를 부여

소켓은 프로세스가 공유하는 네트워크 자원  
스레드가 close()를 호출하거나 프로세스가 죽으면 휘발된다.  
was 프로세스는 스레드가 close()를 호출해도 소켓파일을 유지하고 주기적으로 살아있는지 헬시체크를 한다



gunicorn?  
파이썬의 was  
동기처리 이므로 느리다, 워커 관리가 우수하여 마스터 워커로 사용

uvicorn?
파이썬의 was
비동기처리를 하며 빠르다, 워커로 주로 사용.


gunicorn을 마스터워커로 사용하며 ubicorn을 워커로 사용하는 하이브리드 형태로도 구축가능
systemd에 마스터워커를 등록한다.
```
